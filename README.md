# SecureTECC Platform — Demo

A copy of the SecureTECC managed platform that runs entirely on this machine,
filled with **random test data**. No client, invoice, person, email address or
phone number in it is real, and nothing in it connects to the production
database, Supabase, email, Google or any other outside service.

## Run it

```bash
npm install
npm run dev
```

Open http://localhost:3000 and click **Unlock**: the demo owner account is
pre-filled and any password works. The other demo accounts are
`tech@`, `va@`, `partner@` and `lowvoltage@demo.securetecc.example`.

The first start takes a minute while it builds the database and generates the
data. Later starts reuse it, so changes made during a demo stick around.

```bash
npm run dev:reset   # throw the data away and generate a fresh set
```

`DEMO_SEED=123 npm run dev:reset` produces a different (but repeatable) set.

## Hosting on Vercel

Import the repo into Vercel with the default Next.js settings; no environment
variables are needed. `npm run build` generates the demo data and saves it as
`demo-data/snapshot.tar.gz`, and each server instance loads that snapshot into
memory when it starts (`src/instrumentation.ts`, `src/lib/demo-db-runtime.ts`).

On Vercel:

- Changes made during a demo last until the instance is recycled (after some
  idle time, or on the next deploy), then the data is back to the snapshot.
- Two visitors at once may be served by different instances, each with its
  own copy of the data.
- Dates are relative to the day of the build. Redeploy to bring them current.

To try the Vercel setup locally: `npm run build && npm start`.

## How it differs from production

| Production | Demo |
| --- | --- |
| Supabase Postgres | PGlite, which is Postgres running in-process, stored in `demo-data/pg` (`scripts/demo-db.mts`) |
| Supabase Auth | A cookie naming the demo user (`/api/demo-auth`, `src/lib/supabase/*`) |
| Supabase Storage | Files in `demo-data/storage`, served by `/api/demo-storage` |
| Real records | Generated by `prisma/demo-seed.ts`, dated relative to today |
| Row-level security | Not applied (single fictional organization) |
| Email, Gmail, Drive | Off: `SAFE_MODE=1` |
| AI entry, Analytics, Sentry | Not configured, so those features show their "not set up" state |

Invoice PDFs are rendered the first time each one is downloaded.

PGlite takes one connection at a time, so run one copy of the app against it.
